# השבחה · מעקב חוות דעת

מערכת לאגף השבחה לניהול פרויקטי פינוי־בינוי, בקשות וחוות דעת שמאיות. מאגר אחד משותף ב־Supabase, במקום נתונים שנשמרו בכל דפדפן בנפרד.

## אפיון בקצרה

- **בעיה:** בגרסה הקודמת הנתונים נשמרו ב־localStorage של כל דפדפן: לא משותפים, נמחקים עם ניקוי הדפדפן, וקובץ הנתונים היה פומבי.
- **משתמשים:** צוות אגף השבחה (ענת, אילנית, אגף תכנון).
- **מסלול מרכזי:** כניסה בקוד גישה, סקירה, חיפוש פרויקט, כרטיס פרויקט, הוספה או עדכון של חוות דעת, שליחת מייל.
- **מידע נשמר:** פרויקטים, חוות דעת, הגדרות מייל, יומן פעולות. מחיקה רכה עם סל מחזור.
- **חדש:** סקירת מדדים, רשימת בקשות ממתינות, מגמת רווחיות לפרויקט, ניתוח זמני טיפול, יומן פעולות, שחזור מהסל.

## Supabase

פרויקט `ASHDODMAP` (משותף), כל הטבלאות בקידומת `hb_`:
`hb_projects`, `hb_opinions`, `hb_settings`, `hb_activity`, `hb_access_keys`, `hb_admins`.

RLS פעיל בכל הטבלאות ואין אליהן גישה ישירה. כל קריאה וכתיבה עוברת דרך פונקציות `hb_*` (SECURITY DEFINER) שבודקות קוד גישה (נשמר כ־SHA-256 בלבד) או משתמש מחובר שמופיע ב־`hb_admins`.

הוספת קוד גישה נוסף (למשל לאילנית):

```sql
insert into hb_access_keys(label, key_hash)
values ('אילנית', encode(extensions.digest('HB-XXXX-XXXX-XXXX', 'sha256'), 'hex'));
```

ביטול קוד: `update hb_access_keys set revoked_at = now() where label = '...';`
